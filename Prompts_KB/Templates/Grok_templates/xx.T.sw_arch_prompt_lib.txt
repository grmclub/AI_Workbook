HOW TO USE THIS LIBRARY
══════════════════════════════════════════════════

    FIND YOUR TEMPLATE
    Use the Quick Reference Card at the top
    or browse by category

    COPY THE TEMPLATE
    Copy everything between the dashed lines

    REPLACE VARIABLES
    Replace all {{VARIABLE_NAME}} with
    actual values

    COMBINE TEMPLATES
    Use modifiers (M01-M06) with core prompts
    Example: B01 + M01 = Structural analysis
    with JSON output

    CHAIN TEMPLATES
    Output of one template feeds next
    Example: B02 → B03 → B04 → D01 → F06

══════════════════════════════════════════════════
COMMON CHAINS
──────────────────────────────────────────────────
Quick Overview:
K01 → F06

Full Analysis (Small Codebase):
A01 → B01 → C01 → D01 → E01 → F06 → H05 → I01

Full Analysis (Large Codebase):
A01 → B02 → B03(×N) → A05 → A06 →
C01 → D01 → E01 → F06 → H01 → I01

Risk-Focused:
B01 → C01 → H01 → H02 → H03 → H04 → I02

New Project Onboarding:
B08 → B07 → C06 → G02 → F06 → I05

Security Review:
B01 → C05 → G05 → H02 → L01 → I01

──────────────────────────────────────────────────
MODIFIER COMBINATIONS
──────────────────────────────────────────────────
Any template + M01 = JSON output
Any template + M02 = Markdown output
Any template + M03 = Terse output
Any template + L01 = Evidence-anchored
Any template + L02 = Confidence-gated
Any template + L05 = With assumption registry

    📁 CATEGORY A — Session & Context Management
    [A01] Session Initialize

    text

    TEMPLATE ID: A01
    USE WHEN: Starting any architecture analysis session
    ─────────────────────────────────────────────────────
    You are a principal software architect specializing 
    in reverse-engineering and documenting complex systems.

    SESSION PARAMETERS:
    - Project: {{PROJECT_NAME}}
    - Language: {{PRIMARY_LANGUAGE}}
    - Framework: {{FRAMEWORK}}
    - Analysis Goal: {{GOAL}}
    - Output Format: {{FORMAT}}

    SESSION COMMANDS YOU WILL RECOGNIZE:
    [ANALYZE]   → Produce full analysis now
    [DIAGRAM]   → Generate Mermaid diagrams
    [REPORT]    → Generate architecture document
    [STATUS]    → Show current model state
    [CHECKPOINT]→ Summarize current findings
    [ZOOM: X]   → Deep dive into component X
    [RESET]     → Clear context and start fresh

    OPERATING RULES:
    1. Build architectural model incrementally
    2. Never hallucinate components
    3. Flag assumptions with [ASSUMPTION]
    4. Flag uncertainty with [CONFIDENCE: X%]
    5. Request clarification before major inferences

    Confirm session initialized.
    Await first input.
    ─────────────────────────────────────────────────────
    VARIABLES: PROJECT_NAME, PRIMARY_LANGUAGE, 
               FRAMEWORK, GOAL, FORMAT

    REQUIRED SECTIONS:
    1. COMPONENTS IDENTIFIED
       - List all with type and confidence %

    2. DEPENDENCIES MAPPED

       - What to analyze next

    Format as structured report.
    Max 300 words.
    ─────────────────────────────────────────────────────
    VARIABLES: None (dynamic output)

    [A05] Hypothesis Tracker

    text

    TEMPLATE ID: A05
    USE WHEN: Tracking evolving architectural theories
    ─────────────────────────────────────────────────────
    [HYPOTHESIS UPDATE]

    New evidence from: {{SOURCE}}

    CURRENT HYPOTHESIS REGISTRY:
    {{HYPOTHESIS_JSON}}

    For each hypothesis:
    1. Update status based on new evidence
    2. Add supporting or contradicting evidence
    3. Adjust confidence score
    4. Mark CONFIRMED / SUPPORTED / 
       CHALLENGED / REJECTED

    STATUS ENUM:
    PROPOSED   → New, untested
    SUPPORTED  → Some evidence
    CONFIRMED  → Strong evidence
    CHALLENGED → Contradicting evidence found
    REJECTED   → Disproved

    Add any new hypotheses raised.
    Merge duplicate hypotheses.

    ─────────────────────────────────────────────────────
    VARIABLES: SOURCE, HYPOTHESIS_JSON

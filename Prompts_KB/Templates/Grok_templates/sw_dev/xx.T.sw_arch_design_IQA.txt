

🖥 System Design Interview — Critical Thinking Cheat Sheet

🎯 THE GOLDEN FRAMEWORK


CLARIFY → ESTIMATE → DESIGN → DEEP DIVE → REVIEW

1️⃣ CLARIFY REQUIREMENTS FIRST (5 min)

text

FUNCTIONAL                    NON-FUNCTIONAL
──────────────────────────    ──────────────────────────
□ What does it do?            □ Scale: how many users?
□ Who uses it?                □ Latency requirements?
□ Core features only?         □ Availability target?
□ What is out of scope?       □ Consistency needs?
□ Read or write heavy?        □ Durability requirements?
□ Mobile / web / both?        □ Geographic distribution?

ALWAYS ASK:
"Is this read-heavy or write-heavy?"
"What is the expected scale now and in 2 years?"
"Is strong consistency required or is eventual OK?"
"What is the acceptable latency at P99?"

2️⃣ CAPACITY ESTIMATION (5 min)

text

TRAFFIC                       STORAGE
──────────────────────────    ──────────────────────────
DAU × actions/day             Objects × avg size
= requests/day                = storage/day
÷ 86,400                      × retention period
= requests/second (RPS)       = total storage

QUICK REFERENCE
──────────────────────────────────────────
1M  DAU  × 10 actions = ~116  RPS
10M DAU  × 10 actions = ~1.1K RPS
100M DAU × 10 actions = ~11K  RPS

1KB × 1M req/day  = 1GB/day
1KB × 10M req/day = 10GB/day

BANDWIDTH = RPS × avg payload size
CACHE     = 20% of daily read volume (80/20 rule)

5️⃣ DEEP DIVE — SCALE IT (10 min)

text

SCALING TOOLKIT
──────────────────────────────────────────────────────
PROBLEM              SOLUTION
──────────────────   ─────────────────────────────────
High read load    →  Add cache (Redis/Memcached)
High write load   →  Message queue + async workers
Single DB         →  Read replicas + write primary
DB too large      →  Shard by user_id / region
Hot spots         →  Consistent hashing
Slow queries      →  Add indexes / denormalize
Static content    →  CDN (CloudFront/Cloudflare)
Service overload  →  Rate limiting + circuit breaker
Cross-region      →  Multi-region + replication
Search needs      →  Elasticsearch / Solr
Real-time         →  WebSockets / Server-Sent Events
Large files       →  Object storage (S3) + CDN

🔟 REVIEW & WRAP UP (5 min)

text

ALWAYS CLOSE WITH:

□ Summarize design in 3 sentences
□ Identify your own bottlenecks
□ Name single points of failure
□ Propose monitoring strategy
□ Suggest what to build next

SAY THIS:
"The main bottleneck I see is [X].
 I would address it by [Y].
 The trade-off of that approach is [Z]."

NEVER SAY:
✗ "This design is perfect"
✗ "There are no bottlenecks"
✗ "I am not sure" (say "I would approach
    this by thinking about..." instead)

⚡ COGNITIVE TRAPS TO AVOID

text

TRAP                    INSTEAD
──────────────────────  ──────────────────────────────
Jump to solution        Clarify requirements first
Over-engineer           Ask about actual scale needed
Under-engineer          Ask about growth projections
Ignore trade-offs       Name them explicitly
Stay silent             Narrate every thought
Forget failures         Address fault tolerance
Skip non-functional     Ask about latency/availability
Pick tech by habit      Justify every tech choice
Ignore the interviewer  Treat as collaborative design
Run out of time         Watch the clock. Move forward.

##RTFC Example for skill harvesting for information technology applications

[Role]: Act as a Principal Core Infrastructure Engineer and Quantitative Tech Lead at a top-tier High-Frequency Trading (HFT) firm. You have deep expertise in ultra-low latency systems, kernel-level optimizations, market data feeds, and algorithmic execution.
[Task]: Review the provided text to harvest, isolate, and categorize specialized skills, protocols, and architectural patterns required for HFT development and quantitative engineering.
[Format]: Output a Markdown table with four columns:
    1. Domain (e.g., Low-Latency Systems, Quantitative Math, Market Data/Execution, Hardware Acceleration)
    2. Technical Skill/Tool (e.g., C++20, FPGA, Verilog, FIX Protocol, AVX-512, Kernel Bypass)
    3. Proficiency Indicator (Explicitly flag if the text implies hands-on optimization, architecture design, or just basic usage)
    4. HFT Relevance (A single-sentence explanation of how this skill impacts execution speed, throughput, or pricing accuracy)
[Constraints]: Completely ignore generic software engineering concepts (like standard web APIs, REST, or basic cloud databases). Focus strictly on micro-second/nano-second optimization skills, hardware/software co-design, and mathematical modeling. If the text mentions template metaprogramming, lock-free concurrency, or specific network cards (e.g., Solarflare), prioritize them at the top of the table.

Key HFT Signals This Prompt Will CaptureHardware & Infrastructure: Isolates niche skills like FPGA development (Verilog/VHDL), ASICs, and PCIe interfacing.Network & Protocols: Extracts low-latency networking mastery like Solarflare OpenOnload, DPDK (Data Plane Development Kit), kernel bypass, and raw binary protocols (ITCH/OUCH, FIX).Language Deep Dives: Filters for deep memory management capabilities, such as cache-line alignment, custom allocators, and zero-copy architectures in C++ or Rust.

RTFC Prompt for Architecture Harvesting from a Block Diagram
When extracting architecture from a block diagram using a vision-capable AI, the model must read the layout, spatial relationships, and data flow lines rather than just reading a list of words.
Here is a structured RTFC prompt optimized for interpreting system architecture diagrams of proprietary equity trading systems:

[Role]: Act as a Chief Enterprise Infrastructure Architect and Senior Systems Analyst specializing in low-latency institutional equity trading platforms (OMS/EMS). You have decades of experience converting complex system topography diagrams into structured technical documentation.
[Task]: Analyze the attached architectural block diagram image. Identify all core functional components, subsystems, data flow pipelines, protocols, and infrastructural boundaries relevant to this in-house equity OMS/EMS.
[Format]: Output the architectural breakdown in three distinct markdown sections:
    1. Component Inventory: A bulleted list grouping components by tier (e.g., Inbound Client Tier, Core Processing Tier, Market Connectivity Tier).
    2. Data Flow Pipelines: A numbered list describing the end-to-end paths (e.g., Client Order Entry → Risk Check → Matching Engine → Exchange Feed Handlers), specifying the directional flow (one-way or bidirectional) and network protocols labeled on the lines.
    3. Critical Path Bottlenecks & Inter-Process Communication (IPC): A brief summary identifying how subsystems communicate (e.g., shared memory, message queues) and highlighting any potential single points of failure visible in the diagram layout.
[Constraints]: Do not hallucinate or guess component names; if a block or text label is illegible, label it as [Unreadable Node]. Focus strictly on the technical architecture—ignore any corporate logos, legends, or administrative markings on the diagram. Do not assume vendor integrations unless explicitly printed on a block.
[Input Image]: [Upload or attach your system architecture block diagram image here]

Why This Prompt Works for Vision-Based Architecture Harvesting
    • Spatial and Pipeline Awareness: Forcing the AI to map data flows in a numbered sequence prevents it from simply listing the text boxes it sees scattered around the image.
    • Component Tiering: The prompt forces the AI to map structural boundaries (like firewalls, DMZs, or boundary lines) into logical logical tiers, simulating how a human architect reviews a drawing.
    • Rigid Error Handling: The [Unreadable Node] constraint prevents the AI from inventing a plausible-sounding name for a blurry box in the corner of your diagram.
Would you like to add constraints to explicitly map high-availability/disaster-recovery (HA/DR) lines if they are present in your diagram, or should we include a section to highlight real-time drop copy feeds?

## Microsoft prompt framework is the GCSE Framework (Goal, Context, Source, Expectations)

- Goal: The core action you want Copilot to take.	 
Examples: "Summarize," "Draft an email," "Create a table," "Analyze." 

- Context: The background story, your role, or why you need this information.		 
Examples: "I am prepping for an annual review," or "This is for a non-technical client." 

- Source: The specific data, files, or information pillars Copilot should use.
Examples: "Based on [Document.docx]," or "Use the notes from yesterday's Teams meeting." 

- Expectations: The specific format, tone, length, or constraints of the response.
Examples: "Keep it under 300 words," "Use a professional tone," "Format as three bullet points."

===========
##The 4 Pillars of a Great Copilot Prompt

If you are writing your own prompts from scratch, ensure you include these four elements:

Goal: Clearly state the action you want to take (e.g., create, summarize, find, draft).
Context: Explain the background, tone, and audience.
Source: Point Copilot to the right file or data (e.g., Refer to last week's notes).
Expectations: Define the format (e.g., a 1-page briefing, a bulleted list).

===========

Sample:
[Goal] Draft a project update email 
[Context] for our regional leadership team who hasn't seen the recent numbers. 
[Source] Use the milestones listed in ProjectTimeline.xlsx. 
[Expectations] Keep it concise, use bullet points for wins, and maintain an optimistic but professional tone.

##Generic frameworks

The RTFC prompting framework works universally across all major Generative AI systems and Large Language Models (LLMs), including OpenAI's ChatGPT, Anthropic's Claude, Google Gemini, and Meta AI. Because it relies on universal linguistic structure rather than platform-specific code, it is an AI-agnostic foundational framework.

What RTFC Stands For
The acronym breaks down into four structural components that organize your instructions:
    • R — Role: The specific persona or level of expertise the AI should assume (e.g., "Act as a senior software engineer" or "You are a copywriter").
    • T — Task: The specific job, action, or deliverable you want completed (e.g., "Write a follow-up email" or "Debug this script").
    • F — Format: The structural layout of the required response (e.g., a bulleted list, a markdown table, three paragraphs). 
    • C — Constraints: The explicit limitations or rules the AI must follow (e.g., "Keep it under 150 words", "Avoid generic corporate jargon", or "Do not mention price")

##Specialized Coding Frameworks
##prompting frameworks specifically optimized for software engineering, code generation, and debugging.

Specialized Coding Frameworks
    • CDFC (Context, Definition, Format, Constraints)
        ◦ Context: Explain the tech stack and architecture.
        ◦ Definition: Describe the specific function or logic needed.
        ◦ Format: Request the exact file structure or language.
        ◦ Constraints: Set performance, security, or dependency limits.
		
    • SPEC (Situation, Problem, Expectation, Constraints)
        ◦ Situation: State the current codebase state or framework.
        ◦ Problem: Explain the bug or the feature gap.
        ◦ Expectation: Describe how the working code should behave.
        ◦ Constraints: List language versions or forbidden libraries.
		
    • SARA (Situation, Action, Result, Alternation)
        ◦ Situation: Provide the existing code or error log.
        ◦ Action: Define what the code must accomplish.
        ◦ Result: Specify the expected output or test case.
        ◦ Alternation: Ask for optimized or cleaner alternative approaches.

General Frameworks Adapted for Code
    • RTFC (Role, Task, Format, Constraints)
        ◦ Role: Senior [Language] Developer or Security Auditor.
        ◦ Task: Write, refactor, or debug a specific block.
        ◦ Format: Pure code markdown, with or without comments.
        ◦ Constraints: Code must pass specific linting or time-complexities.
		
    • CARE (Context, Action, Result, Example)
        ◦ Context: Repository setup and database schema.
        ◦ Action: Generate an API endpoint.
        ◦ Result: JSON response payload.
        ◦ Example: Show an example of an existing route.

Reasoning & Debugging Frameworks
    • Self-Refine / Self-Correction
        ◦ Prompt the AI to check its own code.
        ◦ Instruct it to look for edge cases.
        ◦ Force it to fix syntax before outputting.
		
    • Chain of Thought (CoT)
        ◦ Force AI to write pseudocode first.
        ◦ Ask it to explain the logic step-by-step.
        ◦ Generate the final code only at the end.

##The best prompting frameworks for modern C++ development are CDFC, RTFC, and Chain-of-Thought (CoT) with Pseudocode

1. CDFC (Context, Definition, Format, Constraints)
This is the most effective framework for day-to-day feature development because the Constraints and Context fields tightly lock down the language standard.
    • Context: Define your specific compiler, build system, and standard (, , or ).
    • Definition: Describe the algorithm, class, or design pattern you need.
    • Format: Request the separation of headers (.hpp) and implementation (.cpp), or a single-header approach.
    • Constraints: Explicitly forbid legacy practices (e.g., "No raw pointers, use std::unique_ptr"). 

	CDFC Template:
	[CONTEXT]
	I am developing a performance-critical module using Modern C++ [Insert Standard, e.g., C++20]. 
	Compiler: [e.g., GCC 13 / Clang 16]. Build System: [e.g., CMake].

	[DEFINITION]
	Write a thread-safe object pool manager that handles [insert specific resource, e.g., network connections]. 

	[FORMAT]
	Provide the code split into a clean `ObjectPool.hpp` header and an `ObjectPool.cpp` file. Include minimal, high-utility inline Doxygen comments.

	[CONSTRAINTS]
	1. Use strict RAII principles. 
	2. Absolutely no manual memory allocation (`new`/`delete`); use smart pointers (`std::shared_ptr`/`std::unique_ptr`).
	3. Utilize modern concurrency primitives (e.g., `std::jthread`, `std::mutex`, `std::lock_guard`).
	4. Avoid legacy C-style arrays; use `std::vector` or `std::array`.
	5. Ensure zero-overhead abstractions where possible by utilizing `constexpr` and `noexcept`.

2. RTFC (Role, Task, Format, Constraints)**
RTFC is highly optimized for code reviews, refactoring legacy code into modern idioms, and performance optimization.
    • Role: Define the AI as a strict C++ Core Guidelines auditor.
    • Task: Provide old or inefficient code and ask for a modern rewrite.
    • Format: Request a side-by-side or "Before/After" markdown structure with explanations of why changes were made.
    • Constraints: Enforce zero-allocation limits or specific algorithmic time complexities.

	RTFC Template:
	[ROLE]
	You are an expert Senior Systems Architect and a strict follower of the C++ Core Guidelines.

	[TASK]
	Refactor the following legacy C-style code snippet into clean, safe, and modern Modern C++ [Insert Standard, e.g., C++20].

	[Insert Code Here]

	[FORMAT]
	Output the modern code block first. Below the code, provide a punchy, bulleted list explaining the modern features utilized (e.g., move semantics, concepts, ranges) and why they improve safety or performance.

	[CONSTRAINTS]
	1. The refactored code must maintain $O(N)$ time complexity.
	2. Code must be entirely typesafe. No raw casts (`(type)`); use modern casts if necessary.
	3. Optimize for the Return Value Optimization (RVO) by avoiding unnecessary explicit moves on return values.


3. Chain-of-Thought (CoT) with Pseudocode

Because modern C++ features like Metaprogramming (template, concept, requires clauses) or Compile-time evaluation (constexpr, consteval) are highly abstract, forcing the AI to think step-by-step and prevents syntax errors. 

    • Prompt Paradigm: Instead of asking for immediate code, force the LLM to write out the type traits, concepts, or logical constraints in plain English or pseudocode first.

	Copy-Paste CoT Template:
	You need to implement a modern C++ templated serialization function that only accepts types fulfilling a custom concept (`Serializable`).

	Before writing any C++ code, perform the following steps:
	1. Break down the logic of how the `Serializable` concept should check for the existence of a `.serialize()` method at compile time using `requires` clauses.
	2. Outline the step-by-step pseudocode for the serialization algorithm.
	3. Once the logic is verified, generate the complete code conforming to the C++20 standard.

	Summary Checklist for Modern C++ Prompting
	To guarantee "modern" output regardless of the framework you choose, always paste these three rules into your Constraints section:
		• Memory: "No raw pointers or malloc. Use RAII and smart pointers."
		• Type Safety: "Use strongly typed enum class, std::optional, and std::variant instead of raw enums, pointers, or unions."
		• Standard: "Leverage modern algorithms (<algorithm>, <ranges>) instead of manual raw for loops." 
	To help customize this, what specific C++ standard (\(C++17\), \(C++20\), \(C++23\)) are you targeting, and what feature (e.g., multi-threading, ranges, templates)

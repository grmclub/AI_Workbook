Write a parser for the results from [MCP tool]. The raw result is: [paste example result]. Extract the relevant fields, handle missing data gracefully, normalize the format, and return a structured object the agent can reason about without seeing the raw API response.

Prompt 238 · Multi-Tool Workflow

I want an agent to: [describe workflow that requires multiple tools]. I have these MCP tools available: [list]. Design the tool call sequence, what data passes between each call, where to checkpoint results, and what to do if any tool in the chain fails.

Prompt 239 · Tool Preamble Pattern

My agent uses multiple tools and users see a loading spinner during tool calls. Write a preamble instruction: before any multi-step tool use, the agent should send 1-2 sentences confirming it understood the request and stating the first step. This runs before any tool calls start.

Prompt 240 · MCP Test Suite

Write a test suite for my MCP tool integrations. For each tool in [list], include: a happy-path test, a test for invalid input, a test for API timeout, and a test for unexpected response format. Use [test framework]. Mock external API calls — don’t hit live services in tests.

🎯 Category 9 — Outcome-First Prompting (Prompts 241–250) NEW · May 2026

These prompts follow the Outcome-First structure formalized in OpenAI’s GPT-5.5 guide (April 2026): define what “done” looks like, not how to get there. They work equally well with Claude Opus 4.7 and GPT-5.5 — both models respond better to destination-definition than step-by-step instructions.

Prompt 241 · Outcome-First Code Task

Complete this task: [describe what needs to be built]. Success means: (1) [specific testable outcome], (2) [specific testable outcome], (3) [required output fields/format]. Available context: [data/files/APIs]. If evidence is missing for any criterion, ask for the smallest missing piece before proceeding.

Prompt 242 · Customer Issue Resolution

Resolve this customer’s issue end to end. Success means: the eligibility decision is made from available policy and account data — any allowed action is completed before responding — the final answer includes: completed_actions, customer_message, blockers. If evidence is missing, ask for the smallest missing field.

Prompt 243 · Research Task (Outcome-First)

Research [topic] and produce a report. Done means: the report answers [specific question], cites at least [N] verifiable sources, distinguishes between confirmed facts and uncertain claims, and is under [word count]. Do not pad with background information I didn’t ask for.

Prompt 244 · Writing Task (Outcome-First)

Write [content type] for [audience]. Done means: the piece opens with [specific hook type], covers [required points], is [length], avoids [specific patterns to exclude], and ends with [specific CTA or conclusion]. Use only facts from [provided sources]. Mark any claim that needs verification with [VERIFY].

Prompt 245 · Edit Without Inflating

Edit this text for clarity: [paste text]. Rules: preserve length, structure, and genre. Quietly improve clarity and flow. Do not add new claims, sections, or a more promotional tone unless I explicitly ask. If something is factually uncertain, flag it — don’t fix it with a guess.

Prompt 246 · Analysis Task (Outcome-First)

Analyze [data/situation]. Done means: you’ve answered [specific question], ranked [items] by [criteria], identified [N] specific action items with owners, and flagged assumptions I should validate. Don’t describe what analysis you’re going to do — just do it and show the output.

Prompt 247 · Replace ALWAYS/NEVER with Decision Rules

Rewrite this system prompt to replace ALWAYS/NEVER/MUST with decision rules: [paste prompt]. Identify which rules are true invariants (keep the absolute language) and which are judgment calls (convert to “If [condition], then [action]. Otherwise [alternative].”).

Prompt 248 · Personality + Collaboration Separation

I’m writing a system prompt for [AI assistant]. Separate it into two sections: PERSONALITY (how it sounds — tone, warmth, formality) and COLLABORATION STYLE (how it works — when to ask vs. assume, how proactive, how it handles uncertainty). Keep each section under 50 words.

Prompt 249 · Verbosity Control

Rewrite this response at low verbosity: [paste response]. Keep all factual content. Remove: filler transitions (Furthermore, Additionally, It’s worth noting), headers where prose works, bullet points where a sentence works, and the closing summary that repeats what was just said.

Prompt 250 · Content Factual Guardrail

You are writing [content type] for [company/product]. FACTS: use only the following sourced information: [paste facts]. Do not invent: specific customer names, metrics, roadmap dates, product capabilities, or competitive claims. If a claim lacks a source, use a placeholder [PLACEHOLDER: need data on X] rather than a plausible-sounding guess.

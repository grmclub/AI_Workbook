# SKILL.md: Autonomous Research Strategist & Knowledge Base Builder

## Role Definition
You are an expert Research Strategist, Video/Data Analyst, and Interactive Learning Architect. Your job is to autonomously ingest raw research materials (text, images, data sets, infographics) and transform them into a clean, highly connected, and scannable knowledge base optimized for long-term retention and practical application.

## Primary Objective
To extract maximum semantic value from raw data inputs, identify implicit patterns, organize the structural hierarchy, and output a production-grade markdown knowledge base complete with a targeted learning path.

---

## Required Inputs
1. **Source Data**: Images, text blocks, datasets, or infographics (e.g., "The Solar System" data breakdown).
2. **Focus Area (Optional)**: Specific angles or depths the user wants to prioritize.

## Handling Missing/Incomplete Information
* If numerical metrics are missing or implied, state the gap clearly under an "Open Questions/Knowledge Gaps" sub-section.
* Do **not** fabricate secondary statistics or external examples unless explicitly prompted to provide comparative context.

---

## Step-by-Step Workflow Instructions

### Step 1: Ingestion & Core Extraction
Deeply parse the input data. Isolate and capture:
* Hard facts, core metrics, and domain-specific attributes.
* Structural relationships (e.g., scale comparisons, physical layers, classification types).

### Step 2: Apply the 80/20 Rule (Pareto Isolation)
Identify the critical 20% of the data or concepts that deliver 80% of the contextual understanding. High-impact structural elements (e.g., gravitational balance rules, primary categorical distributions) must be prioritized for prominent placement.

### Step 3: Synthesis & Structural Architecture
Organize the extracted knowledge into the standardized execution format detailed below. Use Markdown tables for structured datasets, bold key phrases to maximize scannability, and blockquotes for high-level principles or laws.

### Step 4: Formulate the Adaptive Learning Path
Design a progressive, sequential path to master the material, moving intentionally from fundamental building blocks to advanced mechanical or systemic relationships.

---

## Output Format and Structure

Your final output must strictly follow this structural blueprint:

# [Master Title of Knowledge Base Component]

## 🗂️ Master Index
*   **1. Executive Overview & Core Archetypes**
*   **2. Deep-Dive Data Synthesis**
*   **3. Systemic Frameworks & Mechanics**
*   **4. The 80/20 Value Summary**
*   **5. Open Questions & Knowledge Gaps**
*   **6. Personalized Learning Path**

*   **System Overview**: A concise, 3–5 line macro summary of the domain.
*   **Primary Categorization**: Break down the core types or components observed within the dataset using clear headings or bold terms.

## 3. Systemic Frameworks & Mechanics
*   **Core Dynamics & Balance**: Detail the primary forces or rules keeping this system in place (e.g., how competing metrics balance out).
*   **Anomalies & Outliers**: Highlight unique edge cases or interesting facts present in the data that break standard patterns.

## 4. The 80/20 Value Summary
*   **The Critical Core**: 3–5 bullet points capturing the most valuable, high-leverage insights from the data.
*   **Actionable Takeaways / Mental Models**: How to think about or apply this structured information to broader scenarios.

## 5. Contradictions & Open Questions
*   **Knowledge Gaps**: Identify areas where data is missing, ambiguous, or requires further external investigation.

## 6. Personalized Learning Path
Provide a structured, step-by-step track for a human student to master this specific content:
1.  **Phase 1: Foundations** – Identify the first 1–2 fundamental concepts to learn.
2.  **Phase 2: Mechanics & Interconnection** – Next steps to understand how parts interact.
3.  **Phase 3: Synthesis & Edge Cases** – Advanced concepts or outliers to study last.

---

## Quality Standards & Validation Checks
*   **No Filler**: Omit conversational meta-commentary ("Sure, I can help you with that..."). Output *only* the finished markdown document.
*   **Visual Structure**: Never output dense blocks of unformatted text. Ensure no more than 3 consecutive sentences are used without a bullet point, bold phrase, or table boundary to maximize readability.
*   **Factual Fidelity**: Rely exclusively on data present within the input materials.

## Success Criteria
*   The raw document is compressed into clean, modular, and scannable blocks.
*   Data comparisons are neatly aligned in markdown tables.
*   A clear, foundational-to-advanced learning path wraps up the file.

1/ Claude Power User Guide: Artifacts and Skills
Claude is not only a place to type questions. Its features can help you create useful outputs and repeat successful workflows.
➔ Artifacts turn Claude’s responses into interactive, editable, and shareable work.
You can use Artifacts for:
• Dashboards and charts
• Landing pages and small apps
• Presentations and diagrams
• Documents, reports, and prototypes
Instead of accepting a block of text, ask Claude to create something you can preview, improve, and share.
➔ Skills teach Claude a repeatable way to complete a task.
A Skill can contain:
• Instructions and rules
• Required steps
• Quality standards
• Examples and reference files
• Preferred output structure
Use Skills for tasks you perform repeatedly, such as content creation, research, reporting, onboarding, or document review. Define the method once, then reuse it without explaining everything again.

2/ Connectors, Claude Code, and MCP
These three systems help Claude work beyond a normal chat window.
➔ Connectors give Claude access to information stored in supported external tools.
Depending on availability and permissions, Claude can connect with services such as Google Drive, Slack, and Notion. This allows it to work with your actual files, conversations, and workspace information instead of relying only on what you paste manually.
➔ Claude Code is designed for software development inside the terminal.
It can help developers:
• Understand an existing codebase
• Find and fix bugs
• Write or refactor code
• Run commands and tests
• Review changes before deployment
➔ MCP, or Model Context Protocol, provides a standard way for AI systems to interact with external tools and data sources.
Most everyday users do not need to build an MCP integration themselves. However, understanding its role helps explain how Claude can connect with more specialized systems.

3/ Projects, Automation, and Practical Use Cases
Projects help you keep related work, instructions, and files together.
Create a separate Project for each major area of work, such as:
• Marketing and content
• Customer research
• Business operations
• Product development
• Learning and documentation
Add the relevant files, background information, terminology, and working rules. Claude can then respond with better context without requiring you to rebuild the same setup in every conversation.
Automation takes this one step further.
A simple automation usually follows this structure:
➔ Trigger: something happens.
➔ Action: Claude processes the information.
➔ Output: the result is saved, shared, or sent somewhere.
Useful examples include summarizing new information, preparing reports, organizing research, reviewing documents, and moving information between supported tools.
Start with one repetitive task that has clear inputs and a predictable output.

4/ Combine the 8 Claude Systems
The biggest improvement comes from combining features around one complete workflow.
➔ Artifacts + Skills
Use a Skill to define your process, then produce the result as an Artifact. This works well for dashboards, reports, presentations, landing pages, and reusable content systems.
➔ Connectors + Projects
Bring information from your real workspace into a Project that already contains your instructions, files, and business context.
➔ Connectors + Automation
Use current information from supported tools to trigger recurring actions, summaries, updates, or operational tasks.
➔ Claude Code + Projects
Keep technical documentation and requirements inside a Project, then use Claude Code to work directly with the codebase.
➔ MCP + external tools
MCP can support more advanced connections between Claude, specialized software, internal databases, and business systems.
The goal is not to use every feature immediately. Choose the combination that removes the most repeated work from your day.

5/ A Simple Claude Power User Starting Plan
Follow this order instead of trying to master everything at once:
➔ Step 1: Choose one task you complete every week.
➔ Step 2: Create a Project and add the relevant files, instructions, and context.
➔ Step 3: Turn the process into a Skill if it follows the same steps each time.
➔ Step 4: Produce the final result as an Artifact when it needs to be edited, viewed, or shared.
➔ Step 5: Add a Connector when the required information already exists in another supported tool.
➔ Step 6: Explore Automation when the workflow has a clear trigger, action, and output.
➔ Step 7: Use Claude Code for development tasks that require access to files, commands, tests, or a codebase.
Do not measure progress by how many prompts you write.
Measure it by how much repeated work you remove, how consistently the task is completed, and how easily the workflow can be reused.
